# Roll20 3.5e exporter

In Roll20, open **Game Settings → Mod (API) Scripts**, create a new script, and paste in `export35.js`. Save it, then run one of these commands as a GM:

```text
!export35 --selected
!export35 --name "Character Name"
!export35 --id CHARACTER_ID
```

The script creates a fresh GM-only handout named `3.5e Export - Character Name - timestamp`. It never reuses an older handout that might have been shared. Copy the JSON from the handout into **Import from Roll20** in Barrow Ledger, or save it as a JSON file and choose that file in the dialog. Choose **Review import**, inspect the values and warnings, then **Import as new character**. Preview and Cancel do not save anything. Every completed import creates a separate character and saves pending edits to the previously open sheet first.

The exporter records every instantiated Attribute, including empty and zero current/max values, and reconstructs repeating sections by section and RowID while retaining each original attribute name. Roll20 does not expose arbitrary sheet-default fields as API objects; the script additionally queries a maintained list of important core 3.5e fields with `getAttrByName()`. Extend that list in `CORE` when a known core field needs coverage.

The complete original JSON, including unknown fields, abilities/macros, formulas, empty values, nulls, and zeros, stays attached to the character. **Notes → Roll20 import report → Download original Roll20 JSON** retrieves it. Native Barrow Ledger backups retain it too. Exports and the resulting character must fit the site's 1 MB save limit; larger files are rejected before changing any character.

The importer starts with a blank character and manual calculations. It maps identity, ability scores and temporary adjustments, fixed and repeating multiclass entries, current/maximum HP, saves, AC components, initiative, grapple, standard/custom skill ranks, currency, equipment, feats/features, fixed/repeating weapons, prepared spells, spontaneous usage, and a single psionic reserve. Source totals are retained through explicit offsets. Inspect those offsets before enabling automatic calculations or adding duplicate effects.

Armor check penalties entered as positive deductions are converted to negative modifiers, with a note in the import report. Already-negative penalties keep their sign. If no numeric total is available, the importer combines the normalized penalties from worn armor and shields. The original export remains unchanged.

Arcane spell failure uses the recorded overall total when available, including zero. Armor and shield spell-failure values are summed only when no numeric total exists. Existing saves with the previous double-counting signature are repaired once on load; changed adjustments and explicit overrides are retained with a review warning. This repair does not re-import the character or reset advancement.

Weapon damage that differs from the library or class dice stays in an editable recorded-dice mode, without discarding the catalog identity used for proficiency and other rules. This includes complete formulas such as `1d8+5`; missing or unsupported damage is not silently replaced with standard library dice. Existing saves are repaired once when the retained weapon formula still matches the original export. Explicit dice choices and changed/replacement weapon entries are retained. Review included bonuses and complex formulas after size/class changes; use Combat's library/class-dice option when you deliberately want normal progression instead.

Existing imported characters gain **Skills > Imported bonus review** on loading; do not re-import an old Roll20 file over a levelled-up character. Numeric source totals receive a separate automatic adjustment only when the original misc and armor handling are unchanged. Ambiguous misc/feat overlap stays unchanged until the player selects **Already included in imported misc** or **Separate bonus - no adjustment**. The adjustment uses bonuses from the original import, so later ranks, feats, ability changes, class levels, spent spells, and resource use are not rolled back. A custom adjustment is available for partial overlap. Choices are saved in browser records and native backups.

Explicit imported Weapon Focus and Specialization components are reconciled once against feats present at import. Combat's enhancement/details panel shows separate automatic-only imported attack/damage adjustments; manual miscellaneous values stay intact. Existing saves are repaired only when the corresponding source component and weapon identity still match. Changed components, duplicate/replacement weapons, and explicit zero adjustments are preserved for review. Complete damage formulas can hide included bonuses and are not guessed from their total.

Global attack, flat damage, and extra damage dice import into **Combat > Global weapon modifiers**, honoring the source Action tab's global enabled flag. They affect weapon rolls, not skills, saves, initiative, or spells. Flat damage multiplies on criticals; extra dice are added once. Numeric attack totals retain a separate offset for their already-included global component. Complete damage formulas skip additional global damage until reviewed in the weapon's details. Legacy custom Roll20 macros can disagree with the Action tab toggle; check their intended behavior. These source fields have no bonus type, so do not repeat bonuses already granted by Active effects or feats.

Existing saves receive global modifiers automatically when original weapon components still match. Later levels, weapon enhancements, HP, and resources remain intact. Edited components, duplicate identities, or effects that might already compensate for the missing bonus are left unchanged with the original global values listed in the import report. No re-import is required. The updated exporter also queries global fields and their toggle when they exist only as sheet defaults; update the installed exporter script for future exports.

Numbered arcane and divine spell sections are assigned separately. Ambiguous classes and domain spells get separate manual casting profiles for review. Unknown spells retain their recorded details. Unusual supported weapon damage selectors become fixed adjustments with a warning; arbitrary formulas are never evaluated. Unsupported powers, systems, custom sections, sheet-worker formulas, and macros remain recoverable in the raw JSON. The report identifies unresolved attributes and mapping limitations; it does not certify that every recorded rule has an automated equivalent.

On loading, unchanged class-linked imported casting and psionic profiles adopt automatic advancement. Numeric source totals become original-level adjustments, so later levels and lasting ability changes update caster/manifester levels, slot maxima and power-point reserves. Current preparations and spent resources are not reset. Existing edited profiles, generic casting and domain pools are left for review under Calculations; the one-time repair does not override later manual-progression choices. Missing/formula totals use class progression rather than locking in inferred import-time placeholders.

Older first-level divine spells stored in `repeating_spells` are supported too. If Roll20 has copied a row into `spells11`, only the modern copy is imported. Fresh imports retain prepared/used counts. Existing saves recover missing entries once, without resetting today's slots, preparations, or spent resources. Recovered prepared spells start unprepared; their original counts appear in the spell notes so players can review and prepare them deliberately. Spells manually re-added after import are not duplicated, and changed/ambiguous casting traditions require review instead of being overwritten.

Field names were checked against the [Roll20 community D&D 3.5 sheet](https://github.com/Roll20/roll20-character-sheets/blob/master/D%26D_3-5/charsheet_3-5.html), blob `72bf12e240bd28865e2dd4bd6532665fc5f38cc6`, on September 19, 2026. Other sheet implementations may use different names. `getAttrByName()` can return a formula rather than a computed number; those values are preserved for review.

Additional website mappings belong in `lib/roll20-import.ts` and repeating-field parsing in `lib/roll20-attributes.ts`. Keep the standalone exporter's parser in sync with the latter; `tests/roll20-exporter.test.mjs` checks their parity. Run `node --test tests/roll20-*.test.mjs` for the importer and mocked Roll20 sandbox regressions. A real Roll20 game/export remains an acceptance check; the sandbox tests do not establish live game behavior.

Numeric weapon attack totals are preserved when automating the Weapon Focus/Greater Weapon Focus feats present at import, even if separate Focus fields were missing. Existing unchanged weapons receive the version-two correction without removing later bonuses. Player-edited misc fields and explicit adjustment choices remain intact. Review Imported feat bonus adjustments in Combat if you have manually removed an included bonus from misc. This preserves the source's recorded total; it does not certify that the original total was rules-correct.

Custom imported tower shields and bucklers use case-insensitive proficiency recognition. Changing only capitalization does not grant or remove training. This calculation fix applies to existing saved gear without changing its label, recorded armor values, explicit proficiency choice, or character progress.

Monks no longer lose AC during adoption when armor, a shield or load prevents their unarmored bonus: the importer does not subtract a class bonus that automation will not add. Existing saves receive a one-time correction only for an unchanged original deduction. Later levels, Wisdom gains, equipment, HP and spent resources are preserved; edited miscellaneous AC and explicit overrides remain for review instead of being overwritten.

Psionic powers retain their recorded details under Magic's power notes, including range, duration, target, saving throw and resistance. These notes also appear on posted power cards. Existing saves recover missing details once where the original power and its notes can be matched unambiguously; edited notes and removed powers are left alone. Recovery does not change current levels, augmentation cost, effect formulas, focus, or spent power points. Very long details are bounded with a warning; the complete original text and any macros remain in the retained export. Source macros are never executed or guessed into effect rolls.
